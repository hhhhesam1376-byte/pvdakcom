# PVDak Core — روند نصب آزمایشی و کنترل قبل از پذیرش اطلاعات
نسخه‌های این مرحله: قالب `0.8.7` و هسته مستقل `0.8.0`.

## آنچه Cron انجام می‌دهد و انجام نمی‌دهد
Cron قبلی، قالب را از GitHub روی هاست قرار می‌دهد. فایل‌های `packages/pvdak-core` نیز به‌عنوان **منبع** همراه قالب منتقل می‌شوند؛ این انتقال به معنی نصب افزونه در `wp-content/plugins` یا فعال‌سازی در وردپرس نیست.

هیچ Cron، GitHub Actions، کلید جدید یا مسیر استقرار موازی برای این مرحله ساخته نمی‌شود.

## آماده‌سازی بدون تغییر سایت
دستورات زیر را تحت همان کاربر cPanel مالک فایل‌های وردپرس و در **محیط آزمایشی** اجرا کنید. فرم‌های داده حساس و پذیرش درخواست همچنان باید خاموش بمانند.

```bash
THEME="$HOME/public_html/wp-content/themes/pvdakcom-main"
WP_ROOT="$HOME/public_html"
bash "$THEME/scripts/check-pvdak.sh" "$THEME" "$WP_ROOT"
bash "$THEME/scripts/check-pvdak-core.sh" "$THEME/packages/pvdak-core" "$WP_ROOT"
bash "$THEME/scripts/install-pvdak-core.sh"
```

این سه دستور فقط نحو PHP، آزمون‌های سیاستی، فایل‌های قالب/وردپرس و امکان نصب را بررسی می‌کنند؛ عملیات نصب یا فعال‌سازی انجام نمی‌دهند.

## نصب افزونه بدون فعال‌سازی — پس از پاس‌شدن تست‌ها
با تهیه نسخه پشتیبان و تأیید محیط آزمایشی:

```bash
bash "$THEME/scripts/install-pvdak-core.sh" --install
wp plugin is-installed pvdak-core --path="$WP_ROOT"
wp plugin status pvdak-core --path="$WP_ROOT"
```

اسکریپت قبل از کپی، `php -l` و تست‌های مستقل `tests/pvdak-core/policy-smoke.php` را اجرا می‌کند. از جایگزینی افزونه **فعال** جلوگیری می‌کند و اگر وردپرس کپی جدید را تشخیص ندهد، تلاش به بازگردانی نسخه قبلی می‌کند. این نصب، افزونه را **فعال نمی‌کند**.

## فعال‌سازی فقط برای آزمون کنترل‌شده
این مرحله را روی پایگاه داده/حساب‌های آزمایشی و پس از تأیید آزمون‌های بالا اجرا کنید. قبل از فعال‌سازی، از طریق `wp-config.php` یا سیاست محلی، کلید اضطراری `PVDAK_CORE_DISABLE_INTAKE` را فعال نگه دارید تا حتی با تغییر گزینه‌ها امکان ثبت داده حقیقی نباشد.

```bash
wp plugin activate pvdak-core --path="$WP_ROOT"
bash "$THEME/scripts/check-pvdak-core.sh" "$THEME/packages/pvdak-core" "$WP_ROOT"
```

این چک پس از فعال‌سازی، فایل `scripts/pvdak-core-acceptance.php` را به‌صورت **خواندنی** با WP-CLI اجرا می‌کند. آزمون باید انطباق نسخه نصب‌شده با نسخه موجود در قالب، وضعیت غیرفعال هر دو نوع پذیرش، شورت‌کدها، غیرعمومی‌بودن دو نوع داده حقوقی، مجوز نقش‌ها و ماژول بررسی صلاحیت/قفل‌گذاری را بررسی کند.

برای خاموش‌کردن افزونه در محیط آزمایشی، بدون حذف داده‌ها:

```bash
wp plugin deactivate pvdak-core --path="$WP_ROOT"
```

## معیار توقف قبل از استفاده واقعی
- نتیجه `php -l` و تست سیاستی باید بدون خطا باشد.
- `PVDak Core` در وردپرس **به عنوان افزونه مستقل** شناخته شود و کپی نصب‌شده با بسته منتشرشده یکسان باشد.
- نتیجه `PVDAK_CORE_ACCEPTANCE` بدون شکست باشد.
- آزمایش دسترسی چندکاربره (مدیر/مراجعه‌کننده/وکیل/کارآموز/دانشجو)، آزمون هم‌زمانی دو اتصال MariaDB، حریم خصوصی و بازیابی بک‌آپ باید **عملاً** پاس شده باشد.
- وضعیت «تأیید اداری» یک وکیل، جایگزین بررسی صلاحیت رسمی نیست. هیچ مدرک واقعی، محتوای پرونده واقعی یا اطلاعات حساس وارد نسخه آزمایشی نشود.

**توجه:** موفقیت کدنویسی یا Push به GitHub به معنی موفقیت نصب روی هاست، قبولی تست عملی یا اجازه شروع خدمات واقعی نیست.

## نخستین فعال‌سازی کنترل‌شده پس از نصب غیرفعال (داده واقعی هنوز ممنوع)

گزارش کاربر در 2026-10-22 نشان داد `pvdak-core` نسخه `0.8.0` با موفقیت نصب شده، تست‌های مقدماتی را گذرانده و وضعیت آن **Inactive** است. **نصب را دوباره تکرار نکنید.**

اسکریپت `scripts/pvdak-core-activate-guarded.sh` مانند سایر ابزارهای مدیریتی عمداً همراه قالب در فضای عمومی منتشر نمی‌شود؛ آن را از رفرنس خصوصی دریافت‌شده با Cron استخراج و اجرا کنید:

```bash
bash "$HOME/.pvdak-deploy/deploy.sh" && (
  set -euo pipefail
  R="$HOME/repositories/pvdakcom"
  D="$(mktemp -d "$HOME/.pvdak-deploy/pvdak-activate.XXXXXX")"
  trap 'rm -rf -- "$D"' EXIT
  git -C "$R" archive refs/remotes/pvdak-deploy/main scripts | tar -xf - -C "$D"
  bash -n "$D/scripts/pvdak-core-activate-guarded.sh"
  bash "$D/scripts/pvdak-core-activate-guarded.sh" --check
  bash "$D/scripts/pvdak-core-activate-guarded.sh" --activate
)
```

روش کنترل:
- تطبیق فایل‌های افزونه نصب‌شده با بسته Core قالب و بررسی سایت درست `https://pvdak.com`.
- الزام روشن‌بودن صفحه تعمیرات و خاموش‌بودن هر دو گزینه پذیرش.
- قبل از نخستین فعال‌سازی، تهیه نسخه پشتیبان دیتابیس در **پوشه خصوصی** `$HOME/.pvdak-deploy/backups` با دسترسی محدود.
- پس از فعال‌سازی، اجرای `scripts/pvdak-core-acceptance.php` برای بررسی مجوزهای مدیریت پرونده، شورت‌کدها، نوع داده‌های خصوصی و مقایسه نسخه منبع. سپس تأیید خاموش‌ماندن هر دو فرم و روشن‌بودن صفحه تعمیرات.
- اگر یکی از بررسی‌های پس از فعال‌سازی شکست بخورد، اسکریپت **تلاش به غیرفعال‌سازی افزونه** می‌کند؛ نسخه پشتیبان حفظ می‌شود. **غیرفعال‌سازی به معنی برگرداندن تغییرات نقش‌ها، قابلیت‌های دیتابیس یا رکوردهای وردپرس نیست؛ دیتابیس خودکار بازگردانده نمی‌شود.**
- این تست محدود، جایگزین سناریوهای E2E چندکاربره، حریم خصوصی، بررسی قانونی پروانه و هم‌زمانی واقعی ارجاع پرونده نیست؛ فرم‌های واقعی را فعال نکنید.
