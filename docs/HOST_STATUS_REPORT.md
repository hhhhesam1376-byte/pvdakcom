# گزارش یک‌مرحله‌ای وضعیت نسخه‌ها و تست‌های PVDak

این گزارش برای تشخیص تفاوت **نسخه کد موجود در GitHub**، **نسخه فایل‌های منتشرشده روی هاست** و **افزونه PVDak Core نصب‌شده در خود وردپرس** ساخته شده است.

## دستور آماده برای ارسال به چت

دستور را در SSH همان کاربر cPanel پی‌وی‌داک اجرا کنید:

```bash
bash "$HOME/.pvdak-deploy/deploy.sh" &&
bash "$HOME/public_html/wp-content/themes/pvdakcom-main/scripts/pvdak-status.sh" --test
```

اگر Cron نسخه جدید را قبلاً منتشر کرده و فقط می‌خواهید گزارش بگیرید، همین بخش دوم کافی است:

```bash
bash "$HOME/public_html/wp-content/themes/pvdakcom-main/scripts/pvdak-status.sh" --test
```

خروجی را از `PVDAK_DIAGNOSTIC_BEGIN` تا `PVDAK_DIAGNOSTIC_END` در چت قرار دهید. رمز عبور، کلید، فایل `wp-config.php`، کوکی یا داده پرونده ارسال نکنید. گزارش‌گیر اطلاعات شخصی یا رمز را چاپ نمی‌کند، ولی اگر خطایی از افزونه دیگری همراه خروجی بود، آن را قبل از ارسال بررسی کنید.

این دستور **فقط می‌خواند و تست می‌کند**؛ هسته را نصب/فعال نمی‌کند، زبان وردپرس را تغییر نمی‌دهد، حسابی نمی‌سازد و پذیرش درخواست‌ها را روشن نمی‌کند. تنها بخش اولِ دستور (اسکریپت `deploy.sh` موجود) برای آوردن نسخه جدید قالب عمل انتشار انجام می‌دهد. اگر انتشار ناموفق باشد گزارش‌گیر اجرا نمی‌شود؛ خروجی خطای انتشار را ارسال کنید.

## چه مواردی گزارش می‌شوند؟
- نسخه قالب روی فایل‌های هاست؛ نسخه Core همراه قالب؛ نسخه Core نصب‌شده زیر `wp-content/plugins`
- نسخه وردپرس و PHP، زبان واقعی سایت، نام قالب فعال، موجودبودن `rtl.css`
- نصب/فعال‌بودن افزونه مستقل، مقدار تنظیمات دو نوع پذیرش (در حالت اولیه صفر)
- تطابق محتوای پوشه Core نصب‌شده با کد بسته‌بندی‌شده قالب
- نتیجه ابزارهای PHP lint، تست‌های اولیه محتوا و ایمنی Core
- SHA محلی پوشه مخزن (اگر موجود باشد)، با تأکید بر اینکه **SHA محلی اثبات نسخه منتشرشده نیست**

اگر `Core installed version: MISSING` یا `Core plugin active: NO` دیدید، به معنی مشکل Cron نیست؛ Cron قالب را به‌روزرسانی می‌کند و افزونه مستقل باید جدا نصب/تست شود.

**توجه:** پاس‌شدن این گزارش جایگزین تست واقعی مرورگر، حریم خصوصی، نقش‌ها و هم‌زمانی دو نشست MariaDB نیست.

## روش صحیح برای Cron فعلی (بدون تغییر مسیر انتشار)

اسکریپت واقعی انتشار `scripts/deploy-cpanel.sh` در مخزن از `git fetch` همراه با `git archive` استفاده می‌کند، یعنی `$HOME/repositories/pvdakcom` صرفاً مخزن دریافت‌کننده است و فایل‌های جدید لزوماً در پوشه کاری آن ظاهر نمی‌شوند. انتشار همچنین **عمداً** `scripts` و `docs` را از قالب عمومی حذف می‌کند. پس نبودن `scripts/pvdak-status.sh` در هر دو مسیر **نشانه انتشار ناقص نیست**.

برای گزارش بدون تغییر Cron یا انتشار کدهای مدیریتی در وب، دقیقاً این بلوک را به ترمینال cPanel بدهید:

```bash
(
  set -euo pipefail
  R="$HOME/repositories/pvdakcom"
  D="$(mktemp -d "$HOME/.pvdak-deploy/pvdak-audit.XXXXXX")"
  trap 'rm -rf -- "$D"' EXIT
  git -C "$R" archive refs/remotes/pvdak-deploy/main scripts tests | tar -xf - -C "$D"
  bash "$D/scripts/pvdak-status.sh" --test
)
```

این عملیات فقط اسکریپت‌ها و آزمون‌ها را از **رف انتشار دریافت‌شده** در پوشه موقت خصوصی استخراج می‌کند. گزارش از **مسیر وردپرس واقعی** خوانده می‌شود، در پایان پوشه موقت پاک می‌شود و تغییری در قالب، افزونه، Cron یا پایگاه داده داده نمی‌شود. اگر اولین دستور `git archive` خطا داد، خروجی کامل خطا را ارسال کنید؛ مخزن یا مسیر جدیدی نسازید.

عبارت `UP_TO_DATE` فقط یعنی SHA آخرین انتشار ثبت‌شده با رفرنس دریافت‌شده برابر است. `git rev-parse HEAD` می‌تواند با رفرنس `refs/remotes/pvdak-deploy/main` متفاوت باشد؛ این رفتار در روش فعلی طبیعی است.

## اصلاح جداگانه زبان وردپرس
خروجی واقعی هاست در 2026-10-22 زبان `en_US` را نشان داد. برای تبدیل زبان سایت به فارسی بدون نصب مجدد وردپرس:

```bash
wp language core install fa_IR --path="$HOME/public_html" &&
wp site switch-language fa_IR --path="$HOME/public_html"
```

این دو دستور **تنظیمات زبان وردپرس را تغییر می‌دهند**، اما Cron و فایل‌های سایت را جابه‌جا نمی‌کنند. زبان اختصاصی هر حساب مدیر در بخش پروفایل کاربر باید جدا کنترل شود.

## نتیجه گزارش اجرایی 2026-10-22، ساعت 15:25 UTC — و اصلاح آزمون‌ها

خروجی واقعی هاست نشان داد:
- قالب `pvdakcom-main 0.8.8` فعال، `rtl.css` حاضر، نسخه PHP `8.1.34`، وردپرس `7.1.3`، زبان `en_US`.
- منبع `PVDak Core 0.8.0` داخل قالب هست، اما افزونه **نصب/فعال نشده**. این مشکلِ انتقال قالب نیست؛ افزونه مسیر نصب مستقلی دارد.
- آزمون جست‌وجوی فارسی ۱۱ بررسی را پاس کرد؛ بررسی RTL و فایل‌های آرشیو هم موفق بود.
- تست قالب در مرحله `required WordPress runtime preflight script is missing` شکست خورد، چون اسکریپت قبلاً به اشتباه در مسیر عمومی قالب جست‌وجو می‌شد.
- تست Core در مرحله اجرای مجموعه سیاستی با خروج `255` توقف کرد؛ فایل آزمون در پوشه موقت `scripts/tests` قرار داشت ولی خود هسته در مسیر قالب بود، و پیش‌نیاز بارگذاری منبع Core از پوشه آرشیو فراهم نبود. تا اجرای مجدد نمی‌توان حکم داد که تمام تست‌ها پاس یا رد می‌شوند.

**اصلاح مخزن (بدون تغییر Cron):** `check-pvdak.sh` اکنون WP preflight را از همان پوشه خصوصیِ `scripts` اجرا می‌کند. آزمون Core هم با متغیر `PVDAK_CORE_SOURCE` کد واقعی هسته بسته‌بندی‌شده در قالب را بارگذاری می‌کند؛ اسکریپت نصب نیز همین مسیر را برای تست پیش از کپی دنبال می‌کند. تشخیص خطاهای PHP با پیام واضح‌تری چاپ می‌شود.

برای تکرار همان آزمون بعد از `deploy.sh` یا Cron عادی:

```bash
(
  set -euo pipefail
  R="$HOME/repositories/pvdakcom"
  D="$(mktemp -d "$HOME/.pvdak-deploy/pvdak-audit.XXXXXX")"
  trap 'rm -rf -- "$D"' EXIT
  git -C "$R" archive refs/remotes/pvdak-deploy/main scripts tests | tar -xf - -C "$D"
  bash "$D/scripts/pvdak-status.sh" --test
)
```

این گزارش فقط خواندنی است، تغییری در WordPress/cron نمی‌دهد و اطلاعات پرونده‌ها را چاپ نمی‌کند. **اگر آخرین رفرنس Git دریافت نشده باشد** باید اول همان `bash "$HOME/.pvdak-deploy/deploy.sh"` موجود را اجرا کنید.

- فایل گزارش‌گیر در GitHub هست، ولی انتشار آن در پوشه عمومی قالب **عمداً ممنوع شده است**.

## آزمون جدید پس از فعال‌شدن Core (گزارش 2026-10-22)
خروجی واقعی هاست نشان داد `PVDak Core 0.8.0` **فعال شده**؛ `PVDAK_CORE_ACCEPTANCE: failures=0`، فرم‌های پذیرش خاموش، تعمیرات روشن و پشتیبان خصوصی گرفته شده است. ۲۶ بررسی برچسب‌دار این پذیرش اولیه پاس شده‌اند.

از این به بعد `pvdak-status.sh --test` وقتی Core فعال باشد **یک آزمون وردپرسِ فقط‌خواندنی اضافه** اجرا می‌کند: قفل‌بودن خروجی شورت‌کدهای فرم/پنل برای بازدیدکننده ناشناس، نداشتن قابلیت مدیریت پرونده خصوصی، عدم ثبت مسیر REST خصوصی و روشن‌بودن تعمیرات. این تست فقط کاربر جاری را در حافظه همان پردازش WP-CLI صفر می‌کند و هیچ حساب واقعی ایجاد نمی‌کند. نتیجه تا اجرای مجدد روی هاست **تأیید نشده است**.

```bash
bash "$HOME/.pvdak-deploy/deploy.sh" && (
  set -euo pipefail
  R="$HOME/repositories/pvdakcom"
  D="$(mktemp -d "$HOME/.pvdak-deploy/pvdak-audit.XXXXXX")"
  trap 'rm -rf -- "$D"' EXIT
  git -C "$R" archive refs/remotes/pvdak-deploy/main scripts tests | tar -xf - -C "$D"
  bash "$D/scripts/pvdak-status.sh" --test

```

این تست افزونه فعال را جایگزین نمی‌کند، دیتابیس را تغییر نمی‌دهد و گزینه‌های پذیرش را روشن نمی‌کند. نتیجه PASS بدون E2E چندحساب واقعی و آزمون هم‌زمانی، مجوز پذیرش پرونده واقعی نیست. خروجی جدید هم زمان اجرا `WordPress WPLANG option` را برای روشن‌شدن اختلاف تنظیم زبان با `WordPress site language` گزارش می‌دهد.
