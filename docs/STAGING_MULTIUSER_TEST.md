# PVDak — آزمون دو کاربر واقعی در وردپرس آزمایشی مستقل

## وضعیت فعلی (2026-10-22)
نسخه قالب `0.8.9`، Core `0.8.0` و زبان `fa_IR` روی هاست اصلی تأیید شده‌اند. خروجی 18:18 UTC: تست مصنوعی دو حساب `23/23`، نقش‌ها `68/68` و دسترسی ناشناس `19/19`. **این‌ها جای تست دو حساب با وردپرس و دیتابیس مستقل را نمی‌گیرند.**

اسکریپت `scripts/pvdak-staging-multiuser-e2e.php` اجرای واقعی WordPress database-backed را آزمایش می‌کند ولی عمداً در `pvdak-status.sh --test` اجرا نمی‌شود. گزارش عادی سایت فقط syntax آن را بررسی می‌کند.

## الزام سخت‌گیرانه پیش از اجرا
- یک WordPress نصب‌شده مستقل با **دیتابیس اختصاصی staging** وجود داشته باشد؛ نه همان DB تولید، نه همان `$HOME/public_html` و نه URL اصلی `https://pvdak.com`.
- کد PVDak Core هم در آن محیط آزمایشی فعال باشد. پیش از اجرای تست، کلیدهای دو نوع پذیرش باید OFF و صفحه تعمیرات ON باشد.
- فقط در `wp-config.php` **وردپرس آزمایشی** ثابت `define( 'PVDAK_E2E_ISOLATED_STAGING', true );` اضافه شود. این ثابت را در `wp-config.php` سایت اصلی قرار ندهید.
- افزونه‌ها/اتصال‌های ارسال ایمیل، پیامک و سرویس‌های بیرونی در staging از محیط اصلی جدا یا غیرفعال باشند. حساب‌ها و رکوردها ساختگی هستند و نباید ایمیل واقعی ارسال کنند.
- **پیش از آزمایش روی staging نسخه پشتیبان مستقل بگیرید.** حذف رکوردهای تست به صورت `finally` تلاش می‌شود، ولی شکست‌های سختِ PHP/DB می‌توانند نیاز به پاکسازی دستی روی همان staging داشته باشند.

## اجرا؛ فقط بعد از آماده‌بودن مستقل staging

```bash
# On the staging site owner account, not on production. Set the real separate staging root.
STAGING_WP_ROOT="/absolute/path/to/isolated/staging/wordpress"
R="$HOME/repositories/pvdakcom"
D="$(mktemp -d "$HOME/.pvdak-deploy/pvdak-stage-e2e.XXXXXX")"
# The private tooling must be exported from the existing published main ref.
git -C "$R" fetch origin main
git -C "$R" archive origin/main scripts/pvdak-staging-multiuser-e2e.php |
  tar -xf - -C "$D"
wp eval-file "$D/scripts/pvdak-staging-multiuser-e2e.php" --path="$STAGING_WP_ROOT"
rm -rf -- "$D"
```

قبل از هر اجرا مسیرها را کنترل کنید؛ دستور نمونه را در مسیر اصلی وردپرس اجرا نکنید.

## آنچه آزمون انجام می‌دهد
- دو حساب WordPress دارای نقش مراجعه‌کننده و وکیل آزمایشی ایجاد می‌کند؛ هیچ کدام تأیید هویت حرفه‌ای محسوب نمی‌شوند.
- به هر حساب یک درخواست خصوصی و یک پرونده عضویت خصوصی ساختگی اختصاص می‌دهد.
- برای بازدیدکننده ناشناس و هر یک از دو حساب، شورت‌کدهای درخواست‌های من، پنل من و پنل همکاری را اجرا می‌کند.
- عدم نمایش عنوان درخواست/نام شهر حساب دیگر، دسترسی به درخواست خودش و رد پیوند دست‌کاری‌شده به پروفایل حساب دیگر را بررسی می‌کند.
- فقط کاربران و رکوردهای ایجادشده توسط **همان اجرای تست** را حذف می‌کند و حذف را بررسی می‌کند.

خروجی صحیح: `PVDAK_STAGING_MULTIUSER: checks=20 failures=0 expected=20 cleanup=OK`. نبود هر یک از این شروط به معنای **عدم پذیرش** است، حتی اگر بقیه خروجی‌ها موفق باشند.

این تست هنوز تست دو مرورگر با cookie مستقل، ارسال HTTP واقعی، هم‌زمانی دو مدیر در MariaDB یا کنترل نهایی اطلاعات محرمانه نیست. همه آن‌ها باید پیش از بازکردن پذیرش انجام شوند.
